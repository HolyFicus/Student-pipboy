# Оптимизация нейросети и анализатора расписания для GitHub Pages

Комплексное устранение ошибок распознавания расписания (по скриншоту, тексту и ссылке) на сайте GitHub Pages за счёт гибридной архитектуры: автоматического переключения между облачным мультимодальным ИИ и переработанным локальным табличным OCR/DOM-движком.

## User Review & Critical Decisions

> [!IMPORTANT]
> В плане учтены выбранные вами приоритеты оптимизации для GitHub Pages:

- **Подтверждённый фокус**: Оптимизация всех трёх способов импорта расписания — **по скриншоту**, **по прямой ссылке на сайт вуза** и **по скопированному тексту таблицы**.
- **Подтверждённый режим работы («Оба варианта с автоматическим переключением»)**:
  1. **Уровень 1 (Облачный мультимодальный ИИ из браузера)**: При наличии интернета на GitHub Pages запросы отправляются через CORS-совместимый публичный мультимодальный ИИ-шлюз (с передачей сжатого чёткого изображения и строгой JSON-схемы расписания), что даёт качество распознавания на уровне Google AI Studio без необходимости запускать собственный Node.js-сервер.
  2. **Уровень 2 (Улучшенный автономный табличный OCR и DOM-парсер)**: Если облачный шлюз недоступен, превышен лимит времени или включён локальный режим, система автоматически и без ошибок переключается на исправленный локальный распознаватель сетки таблицы и текста в браузере.

---

## 1. Overview & Core Concept

- **Почему возникали ошибки на GitHub Pages**:
  1. *На скриншотах*: прежний детектор вертикальных линий таблицы учитывал любые тёмные пиксели без проверки непрерывности линии, из-за чего вертикально выровненные начала строк текста внутри широких колонок («предмет», «комм.») ошибочно принимались за границы столбцов и сдвигали колонки. Кроме того, склейка узких ячеек (`Пн`, `1)`) и широких ячеек в один длинный холст приводила к пропуску мелких ячеек в Tesseract.
  2. *По ссылке*: в статическом режиме GitHub Pages поле URL расписания ранее не загружало HTML-таблицу страницы вуза.
  3. *По тексту*: при копировании таблицы прямо со страницы расписания (`Ctrl+C` → `Ctrl+V`) табуляции (`\t`) и переносы строк внутри ячеек не разбирались как 7-колоночная структура.
- **Что изменится**:
  - На GitHub Pages заработает гибридный конвейер ИИ, сочетающий облачное мультимодальное распознавание скриншотов/текста и точный локальный алгоритм выделения ячеек таблицы с поддержкой `rowspan`, подгрупп `1)`, `2)`, `3)` и диапазонов недель (`до 9 недели`, `после 9 недели`).

## 2. User Experience & Visual Design

- **Прозрачная индикация этапа и режима работы**:
  - В окне «Интеллектуальное распознавание расписания» отображается живая шкала прогресса с указанием активного контура: `Мультимодальный ИИ-анализ таблицы...` → при необходимости мгновенный переход на `Локальный табличный OCR-анализ по колонкам...`.
  - Никаких сбоев или пустых ответов: если один из уровней не смог распознать нестандартный формат, второй уровень автоматически подхватывает задачу и открывает интерактивную таблицу предпросмотра для проверки перед сохранением.
- **Поддержка копирования таблиц с портала вуза (`Ctrl+C` / `Ctrl+V`) и прямых ссылок**:
  - Если студент вставляет ссылку на страницу расписания вуза, система извлекает HTML-таблицу напрямую через каскад CORS-прокси (с сохранением объединённых ячеек `rowspan` для дней недели и времени) менее чем за 1 секунду.
  - Если студент копирует таблицу мышью на сайте вуза и вставляет её во вкладку «Текст», парсер автоматически распознаёт колонки, разделённые табуляцией (`\t`), и собирает расписание мгновенно.

## 3. Key Product Decisions & Trade-Offs

- **Решение 1: Фильтрация границ таблицы по непрерывным сегментам (`Continuous Line Run`)**
  - *Выбранный подход*: Вертикальная и горизонтальная граница таблицы засчитывается только тогда, когда пиксели рамки образуют **непрерывные прямые отрезки** (длиной не менее 25 пикселей подряд без разрывов), а положение колонок сверяется с пропорциями 7-колоночной сетки (`дата | время | подгр. | предмет | преподаватель | ауд. | комм.`).
  - *Почему*: Буквы текста всегда прерываются межстрочными интервалами каждые 10–14 пикселей, тогда как линия таблицы непрерывна. Это полностью исключает ложные срабатывания внутри текста и смещение столбцов.
- **Решение 2: Поколоночное и построчное распознавание вместо единой длинной ленты**
  - *Выбранный подход*: В локальном OCR-режиме колонка `дата` (`Пн`–`Сб`) определяется по 6 объединённым блокам дня недели, колонка `время` и `подгр.` распознаются с цифровым приоритетом, а текстовые ячейки каждой строки (`предмет`, `преподаватель`, `ауд.`, `комм.`) группируются построчно с чёткими разделителями и словарной автокоррекцией академических терминов и ФИО.
  - *Почему*: Исключает потерю мелких цифр времени и номеров подгрупп и ускоряет локальный OCR в 2 раза.
- **Решение 3: Каскад «Сервер AI Studio → Облачный ИИ-шлюз в браузере → Локальный табличный OCR/DOM»**
  - *Выбранный подход*: Единый диспетчер `parseScheduleHybrid` проверяет доступность серверного API (в AI Studio), затем на GitHub Pages обращается к публичному мультимодальному ИИ-шлюзу с таймаутом 14 секунд, а при любой сетевой ошибке или в офлайн-режиме выполняет локальное табличное распознавание.

## 4. Technical Architecture & Data Strategy *(Technical Reference)*

### Architecture & Component Diagram

```
┌────────────────────────────────────────────────────────────────────────────┐
│                Вкладка «РАСПИСАНИЕ» — Модальное окно ИИ                    │
│       Входные данные: Скриншот (PNG/JPG) | Ссылка (URL) | Текст (TSV)      │
└─────────────────────────────────────┬──────────────────────────────────────┘
                                      │
                                      ▼
┌────────────────────────────────────────────────────────────────────────────┐
│                   Гибридный диспетчер расписания                           │
│                                                                            │
│  1. Режим AI Studio (/api/ai/parse-schedule -> Gemini Server API)          │
│     │ (если хост *.github.io или сервер недоступен)                        │
│     ▼                                                                      │
│  2. Публичный мультимодальный ИИ-шлюз (CORS Vision / Text JSON API)        │
│     │ (автоматическое переключение при таймауте / офлайне)                 │
│     ▼                                                                      │
│  3. Локальный движок GitHub Pages:                                         │
│     • Скриншот -> Детектор непрерывных линий сетки + Построчный OCR        │
│     • Ссылка   -> Каскад CORS-прокси + DOMParser <table> с учётом rowspan  │
│     • Текст    -> Табличный TSV-парсер (табуляции, дни, подгруппы, недели) │
└─────────────────────────────────────┬──────────────────────────────────────┘
                                      │
                                      ▼
┌────────────────────────────────────────────────────────────────────────────┐
│         Интерактивная 7-колоночная таблица предпросмотра и правки          │
│   Автосинхронизация с учебной неделей (9 нед.) и Калькулятором оценок      │
└────────────────────────────────────────────────────────────────────────────┘
```

### Data Model & State

- **Валидация результата ИИ**: Любой ответ (от облачного шлюза или локального парсера) проходит через единый нормализатор `validateAndCleanParsedSchedule(rawClasses)`, который:
  - Проверяет корректность кодов дней (`MON`..`SAT`), формата времени (`ЧЧ:ММ`), номеров подгрупп (`1`..`4`) и чётности недель (`UPPER`, `LOWER`, `BOTH`).
  - Автоматически извлекает `weekFrom`, `weekTo` и `weekRangeLabel` из комментариев (`до 9 недели`, `после 9 недели`).
  - Очищает артефакты OCR в названиях дисциплин, аудиториях и ФИО преподавателей.

### Interactive Component & State Mapping

- **Переключатель и индикатор режима в модальном окне ИИ**:
  - Пользователь видит текущий этап обработки и источник распознавания (`Распознано через облачный ИИ` или `Распознано локальным табличным анализатором`), а также может в любой момент переключиться на ручную правку ячеек в таблице предпросмотра.
